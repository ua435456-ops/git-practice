# Мои заметки по Git(версия 1)

## Что такое Git
Git — это система контроля версий. Она хранит историю изменений файлов в проекте. Каждое изменение (коммит) — это снимок состояния проекта. Git позволяет вернуться к любому прошлому состоянию, посмотреть, что менялось, работать над проектом с другими людьми, не теряя изменения друг друга.

## Зачем нужен
хранить историю, возвращаться к прошлым версиям, работать в команде без конфликтов, экспериментировать в ветках без риска.

## Коммит
Коммит — это снимок состояния проекта в конкретный момент. Внутри: состояние файлов, хеш, автор, дата, сообщение, ссылка на предыдущий коммит. Коммиты образуют цепочку истории.
## Staging area
Staging area — промежуточная зона, куда попадают файлы после git add. Там они ждут коммита. Позволяет выборочно коммитить — не всё сразу, а то, что нужно.

## Репозиторий
епозиторий — это обычная папка + .git. Отличается тем, что в ней хранится история (коммиты, ветки, настройки). Обычная папка этого не умеет.

## Что будет, если удалить .git
Пропадёт вся история — коммиты, ветки, настройки. Файлы на диске останутся. Папка снова станет обычной

## Хеш коммита
Хеш — уникальный номер коммита. Помогает найти коммит, сравнить два коммита, откатиться к нужному.

## Ветка (branch)
Ветка — отдельная линия разработки. Указатель на определённый коммит. Позволяет экспериментировать и разрабатывать фичи в изоляции, не трогая основную ветку. В каждой ветке — своя история коммитов.

Зачем нужны:
Новая фича — отдельная ветка.
Багфикс — отдельная ветка.
Эксперимент — отдельная ветка.
Командная работа — каждый в своей ветке.

## HEAD
HEAD — указатель на то, где ты сейчас находишься. Всегда смотрит на текущую ветку и последний коммит этой ветки. При переключении ветки — переезжает. Новые коммиты идут туда, куда смотрит HEAD.

В git log отображается как (HEAD -> имя_ветки).

HEAD — текущий коммит.
HEAD~1 — предыдущий коммит.
HEAD~2 — два коммита назад.
HEAD~3 — три назад.

## Fast-forward
Fast-forward — слияние без создания нового коммита. Бывает, когда целевая ветка не двигалась с момента ответвления. Git просто переставляет указатель на последний коммит сливаемой ветки.


## Команды GIT

Работа с репозиторием:
git init — создать репозиторий (добавить .git к папке).
git status — посмотреть состояние файлов.
git add файл — добавить файл в staging area.
git add . — добавить все файлы.
git commit -m "сообщение" — сделать коммит.
git log — посмотреть историю коммитов.
git log --oneline — история в коротком формате.
git rm --cached - удалить файл из staging area
git log --oneline -- имя_файла — история конкретного файла.
git ls-files — все отслеживаемые файлы.
git show хеш(можно еще HEAD) --stat — какие файлы в коммите.
git push — отправить изменения на GitHub.
git pull — забрать изменения с GitHub.
git diff	Рабочая папка vs последний коммит
git diff --staged	Staging vs последний коммит
git diff HEAD	Рабочая папка + staging vs коммит
git diff <коммит>	Рабочая папка vs конкретный коммит
git diff <коммит1> <коммит2>	Разница между двумя коммитами
git diff <файл>	Разница только в файле
git show <коммит>	Что изменилось в конкретном коммите

git commit --amend -m "Новый правильный текст" - Она просто перезаписывает последний (!!!!!еще не отправленный на сервер!!!!) коммит.
!!!!! Если уже запушил — придётся git push --force (опасно, если работаешь в команде).


git reset — буквально «отматывает время назад». Он удаляет коммиты из истории. Его можно безопасно использовать только локально (до того, как вы сделали push). Если удалить коммиты, которые уже на GitHub, у всей команды сломается история.
--soft — откатывает коммит, но оставляет изменения в staging.
--mixed — откатывает коммит и staging, оставляет в рабочей папке.
--hard — удаляет всё (коммит, staging, рабочую папку). Опасно!

git reset --hard HEAD~1    «Перемести HEAD на один коммит назад, и удали всё, что было после.»

--soft HEAD~1 — HEAD на C, но изменения из D — в staging. Файлы не тронуты.
--mixed HEAD~1 (по умолчанию) — HEAD на C, изменения из D — в рабочей папке, не в staging.
--hard HEAD~1 — HEAD на C, всё из D — удалено. Опасно.

git revert — создает новый коммит, который делает противоположное действие (отменяет изменения старого коммита). История не стирается, а идет вперед. Это безопасный способ отмены изменений, которые уже улетели в общий репозиторий.

reset — для локальных коммитов, которые не пушил. Переписывает историю.
revert — для уже запушенных коммитов. Безопасно — не ломает историю.

git restore <имя_файла> - вернуть удаленный файл, если он был в последнем коммиите
git stash — спрятать(временное хранилище для незакоммиченных изменений.)
git stash list — список спрятанного.
git stash pop — достать последнее.
git stash apply stash@{0} — достать конкретное.
git stash drop	Удалить последнее без доставания
git stash clear	Удалить все stash
git stash show	Что в последнем stash
git stash show -p	Подробно (как git diff)
!!!! git stash -u   чтобы прятать и untracked файлы

git stash pop	  Достать + удалить из stash
git stash apply	  Достать, но оставить в stash

Опечатка в сообщении	  git commit --amend -m "правильно"
Забыл файл	              git add файл → git commit --amend --no-edit
Лишний файл в коммите	  git rm --cached лишний → git commit --amend --no-edit
Изменить и то, и другое	  git add файл → git commit --amend -m "новое"


Работа с ветками:
git branch — посмотреть все ветки (текущая — со *).
git branch имя — создать ветку.
git checkout имя — переключиться на ветку.
git checkout -b имя — создать + переключиться.
git merge имя — слить ветку имя в текущую.
git branch -d имя — удалить ветку.


## Терминал

Git Bash — эмуляция Linux-терминала на Windows. Позволяет использовать Linux-команды.
PowerShell — стандартный терминал Windows. Команды другие (ls -Force вместо ls -a).
Команды:
pwd — где я сейчас.
ls — что в папке.
ls -a — что в папке, включая скрытые.
cd имя — перейти в папку.
cd .. — на уровень вверх.
cd ~ — в домашнюю папку.
mkdir имя — создать папку.
touch файл — создать пустой файл.
echo "текст" > файл — создать файл с текстом.
rm файл — удалить файл (безвозвратно, не в корзину).
~ — домашняя папка (/c/Users/user). Не корень диска.

## Теория тестирования (кратко)
QA — обеспечение качества, предотвращает баги на этапе планирования.
QC — контроль качества, находит баги в готовом коде.
Testing — часть QC, конкретная проверка.

Smoke — тест критического минимума функций для работоспособности.
Regression — проверка, что новые изменения не сломали старое.
